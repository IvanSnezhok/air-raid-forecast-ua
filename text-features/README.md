# Текстові сигнали з Telegram для прогнозу тривог

Мета: додати до моделі прогнозу тривог (основний пайплайн у `air-raid-forecast/`) ознаки з публічних Telegram-каналів моніторингу: про що і про які області пишуть *до* моменту прогнозу.

## Головне правило: тільки те, що було опубліковано до моменту прогнозу

Для кожного поста рахується `available_at`, момент, коли текст став публічним:

| Як отримали пост | `available_at` |
|---|---|
| live (`collect_telegram.py follow`) | момент, коли ми його побачили (`collected_at`) |
| історія (`backfill`), без редагування або редагування ≤ 2 хв | `date` (час публікації) |
| історія, відредагований пізніше ніж через 2 хв | `edit_date` (ми маємо лише фінальний текст) |

Ознаки в момент прогнозу T рахуються лише з постів, де `available_at < T` (строго). Для годин поза періодом збору ознаки = NaN, а не 0, щоб «ми не збирали» не виглядало як «тиха ніч». Тест `tests/test_no_leakage.py` перевіряє це механічно: ознаки в T не змінюються, якщо видалити всі пости з `available_at >= T`. Перевірено, що тест падає, якщо навмисно додати «погляд у майбутнє» на 1 хвилину.

Залишкове зміщення, про яке треба памʼятати: пости, видалені каналом до backfill, ми не побачимо зовсім. Live-збір цього не має, тому `follow` варто запустити якомога раніше.

## Як запустити на своєму компʼютері

Telegram недоступний з хмарного середовища, тому збір іде локально з твоїми власними API-ключами.

1. Отримай `api_id` і `api_hash` на https://my.telegram.org → API development tools.
2. Встанови залежності і задай ключі тільки через змінні середовища (ніколи не комітити):
   ```bash
   cd text-features
   pip install -r requirements.txt
   export TG_API_ID=...
   export TG_API_HASH=...
   ```
3. Історія (перший запуск попросить номер телефону і код, сесія збережеться в `~/.airraid_telegram.session`, поза репо):
   ```bash
   python collect_telegram.py backfill --since 2024-01-01
   ```
   Скрипт можна перезапускати: він дочитує лише нові пости.
4. Live-збір (тримати запущеним, наприклад у `tmux`):
   ```bash
   python collect_telegram.py follow
   ```
5. Побудувати погодинні ознаки:
   ```bash
   python features.py --out data/text_features.parquet
   python -m pytest -q tests
   ```

Для GitHub Actions (там немає файлу сесії): один раз локально згенеруй рядок сесії і поклади його в секрет `TG_SESSION_STRING` разом з `TG_API_ID` і `TG_API_HASH`:
```bash
python -c "import os; from telethon.sync import TelegramClient; from telethon.sessions import StringSession; c=TelegramClient(StringSession(), int(os.environ['TG_API_ID']), os.environ['TG_API_HASH']); c.start(); print(c.session.save())"
```
Цей рядок дає повний доступ до акаунта Telegram: тільки в секрети, ніколи в код чи логи.

Список каналів у `channels.py` (Повітряні сили `kpszsu`, `war_monitor`, `deraketaua`, `raketa_trevoga`, `UkraineAlarmSignal`). Перед довгим backfill варто перевірити, що канали досі активні.

## Ознаки

Таблиця на рівні (origin, region), де origin — початок UTC-години, як в основному пайплайні; назви областей збігаються з колонкою `region` волонтерського датасету. Вікна w = 30, 60, 180 хв.

- **Національні** (однакові для всіх областей): `tg_msgs_{w}m`, `tg_{клас}_{w}m` для класів `drone, cruise, ballistic, missile, kab, launch_platform, launch, direction, all_clear`, а також `tg_min_since_{launch_platform|ballistic|cruise|drone|kab}` (хвилин від останньої згадки, максимум 1440).
- **Регіональні**: `tg_reg_any_{w}m` (згадки області), `tg_reg_{drone|missile|kab|all_clear}_{w}m` (згадка області разом з типом загрози), `tg_reg_min_since_any`, `tg_reg_min_since_threat`.
- `tg_covered`: 1, якщо година всередині періоду збору.

Найцінніший очікуваний сигнал: `launch_platform` (зліт Ту-95/Ту-160/МіГ-31К), який зазвичай публікують *до* пусків, і `tg_reg_drone_*` («шахеди курсом на …»), які випереджають тривогу в сусідній області.

Класифікація зроблена простими regex-правилами в `lexicon.py` (пояснювано і відтворювано). Відомі обмеження описані там же: Київ/Київщина часто змішують, «Дніпро» буває річкою.

## Готові публічні датасети (перевірено 2026-10-11)

- **Kyrychenko, Telegram channels and posts about the Russo-Ukrainian war** (Zenodo, CC BY 4.0, 49 ГБ): 79.6 млн постів із 4 687 каналів, 2015-09 → 2024-03-26. Новинні та пропагандистські канали, а не моніторингові; закінчується у березні 2024. Підходить хіба для перевірки «новинного фону» на 2022–2024, для поточного прогнозу не придатний. https://zenodo.org/records/16949193
- **Massive Missile Attacks on Ukraine** (Kaggle, Petro Ivaniuk): щоденні звіти Повітряних сил про запущені/збиті ракети і дрони. Звіт публікують наступного ранку, тому для прогнозу можна брати лише «вчорашню атаку» з моменту публікації звіту (≈ 09:00 Київ). Колонки та ліцензію не перевірено: Kaggle недоступний з хмари. https://www.kaggle.com/datasets/piterfm/massive-missile-attacks-on-ukraine
- **lbgos/AirAlerts** (GitHub, без ліцензії): готового датасету немає, але це найближчий приклад того самого підходу (Telethon, ті самі канали, правило «редагування пізніше 1 хв рахується від часу редагування»). Ідеї беремо, код ні. https://github.com/lbgos/AirAlerts

Готового відкритого архіву моніторингових каналів (`kpszsu`, `war_monitor` тощо) з точними часовими мітками я не знайшов, тому власний збір потрібен.
